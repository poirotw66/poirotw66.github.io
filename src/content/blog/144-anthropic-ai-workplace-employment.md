Anthropic 2026 年 10 月發布的[內部工作研究](https://www.anthropic.com/research/employment-at-anthropic)，並列兩個值得追問的變化：junior 技術職新聘占比一年多來從 27% 降到 9%，員工指派的互動式 Agent 到 8 月則記錄了相當於人類操作者六倍的 runtime。前者關係到誰還有機會進入技術團隊，後者提醒我們，Agent 做得更多不代表人類工作就等比例變少；人也要分流、檢查並決定下一步。

這份報告的價值，是讓我們看到一家高度使用自家 AI 的公司如何改變招聘、任務與監督方式。它不是外部審計，也不能證明 Claude 導致了聘用比例變化，更不能直接預測其他企業或整體勞動市場。讀數字時，必須先看分母，再看它真正量到什麼。

> **花花的判斷**
>
> Agent 把工作做快之後，瓶頸可能移到人的注意力；而新人能不能進場，仍要看企業是否保留能學習與承擔責任的工作。

## 先變的是聘用組成，不是技術人力消失

Anthropic 的技術部門裡，junior-level 員工占比從 2025 年初的 21% 降到報告觀察期間的 14%；在技術職新聘者中，junior 的占比更從 27% 降到 9%。這兩組分母不同：前者是技術部門現有人員，後者是新聘技術職。它們都描述組成比例，不能解讀成 junior 人數減少了相同比例。

報告也指出，同期 Anthropic 持續擴張，技術職的絕對聘用仍增加；技術部門占全公司員工的比例則從 61% 降到 56%，因為銷售、財務與招募等職能成長更快。公司擴張時的職能組合改變，和 AI 自動化可能有關，但兩者不能混為一個原因。管理者回報部分核心工程與研究團隊開始減少較低職級的聘用，約三分之一 ML 主管與五分之一軟體工程主管表示因 AI 而少聘；這是主管調查與公司招聘紀錄的觀察，不是對外部雇主的抽樣。

這個訊號和 [Anthropic 以實際使用資料衡量勞動市場曝光度的研究](/blog/05-labor-market-impacts-of-ai/)回答不同問題。那篇看美國職業任務與勞動市場資料；這份新報告則走進單一公司的內部，觀察職缺、員工、Agent 使用與工作內容如何同時變動。

## 六倍 runtime 是 Agent 工時，不是六倍產能

Anthropic 根據 Agent session telemetry 計算，2026 年 3 月所有自主與互動式 Agent 的總工作時數首次超過人類工時；若只看員工指派的互動式 sessions，8 月 Agent runtime 約為操作者人類工時的六倍。這個「工作時數」包含推論與實際工具操作，排除超過 30 分鐘的等待，並把子 Agent 一併計入；人類基準則以員工人數乘上每週 40 小時估算。因此它衡量的是執行時間規模，不是等量的人類工時，也不是六倍產出或價值。

人類注意力反而成了另一個限制。報告估計，在多輪互動式 sessions 中，約 80% 的 session wall-clock 時間是在等待人類輸入；這表示 Agent runtime 擴張的同時，許多任務仍停在交接點。研究再將輸出 tokens 轉成單字數，以每 token 0.75 個英文單字、每分鐘閱讀 250 個英文單字的假設估算：即使非技術職能，要把互動式 Agent 的所有輸出讀完，也可能超過半個工作週。這是閱讀量換算，不代表員工實際逐字讀完，也不等於每段輸出都需要同等審查。

這種變化也出現在工作本身。Anthropic 將撰寫多 Agent 規格、讓一個 Agent 檢查另一個、監控工作流程等任務稱為「meta-work」。報告估計，這類工作占平均每位員工互動式 sessions 的比例，從 2025 年秋季約 10% 升至 2026 年春季的 22%。這個比例來自自動分類約 2,000 則一行 session 摘要，分類結果是工作內容的近似值，不是對員工工時的直接計時。四月的開放式員工問卷中，27% 的回覆提到 Claude 帶來生產力提升，20% 提到職務從親自執行轉向管理 Claude；這反映員工描述的經驗，也不是全公司的客觀產能統計。

> **花花的工程提醒**
>
> Agent 的 runtime、輸出量和完成工作不是同一個分母。導入評估要把等待、人工分流、審查、返工與品質一起記錄，才看得出瓶頸搬到哪裡。

## 產出增加的證據，仍受採用選擇影響

Anthropic 以 192 位採用 coding agents 的工程師，對照研究期間未採用的 74 位工程師，追蹤個人程式碼新增量。作者使用個人與月份固定效果比較採用前後，並指出採用後新增程式碼上升。不過，採用不是隨機分派：即將推動大型專案的人可能更有動機先用工具；全自動 Agent 的早期採用者在採用前也已呈現較快的產出上升。因此，這項分析比單純比較使用者和非使用者更細緻，仍不能單獨證明工具造成全部變化。

品質也只檢查了部分可觀察代理指標。研究比較同一員工、同一月份、同一程式目錄中由 Agent 與人直接撰寫的程式碼，沒有發現後續刪除或 revert 等指標的差異。這不等於程式碼品質全面相同：可讀性、維護成本、隱藏錯誤、架構決策與長期商業影響都不會由這些代理指標完整捕捉。報告本身也明確提醒，新增更多程式碼不等於更好的程式碼或更大的商業價值。

跨職能的輸出指標也要同樣小心：報告記錄律師處理更多合約、應付帳款處理更多發票、業務代表成交更多客戶；這些數字與 Agent 擴散同期上升，但公司營收成長、案量變化和員工挑選何時採用工具都可能影響結果。它們是 Anthropic 內部可量測工作的產出訊號，不是獨立驗證的因果效果。

## 工作沒有只被刪除，也被重新分配

17 場員工訪談補上數字看不到的職務轉換。一個產品設計團隊先建立內容脈絡，讓 Agent 能協助產生產品文字；團隊接著轉向撰寫 Agent prompts 與模型評測。這是報告中的單一團隊案例，不能代表所有寫作者的去向，但清楚呈現同一群人的工作可能從直接產出文字，轉為設計與檢查模型行為。另一個研究團隊的案例也呈現類似分工，可讀 [Claude-shaped science：Agent 算得快，人仍要選對問題](/blog/131-anthropic-claude-shaped-science-agentic-research-workflow/)。

報告也記錄，2026 年在 Anthropic 任職至少一年的員工，每月跨部門轉調的可能性比 2025 年高 50%；整個團隊也曾把原有工作交給 Agent 後重新配置。這些公司內部紀錄說明工作重新分配正在發生，卻沒有證明 AI 是每次轉調的唯一原因，更不能回答新進員工是否有同等的轉換機會。對 junior 而言，聘用占比下降可能比在職者轉調更值得追蹤：公司可以重新安排現有員工，卻不一定因此保留新人學習基本工作、累積判斷力的入口。

Anthropic 也分析數千份招聘面試評分卡。提到候選人 AI 工具使用經驗的評語，在技術職評估中由 2024 年約 5% 增至 2026 年的三倍，在非技術職由約 7% 增至四倍；技術職面試中，對自主性與判斷力的評語增加，領域專業討論占比下降。這些是面試官評語的文字分析，不等於候選人能力的標準化測驗；它顯示的是公司如何描述理想人才，不能直接得出 AI 技能已普遍取代專業知識。

## 企業該追蹤工作流，不只追蹤 Agent 時數

這份報告對導入團隊最實用的提醒，是把工作拆到能看見任務移動的程度。除了 Agent 呼叫、runtime 和產出量，也應記錄人工等待與審查時間、例外處理、返工、品質、員工轉調，以及 junior 職缺與新聘占比。如此才分得清楚，Agent 是省下了某段工作、擴大了可處理的需求，還是把執行轉成了監督與協調。

同時，企業要為被自動化的任務設計新的學習路徑：若 junior 不再負責部分基礎實作，哪些任務能讓他們在可審查的範圍內累積領域知識與判斷？在職員工可以內部轉調，不代表新人自然會找到入口。這也是為什麼 [Agentic Coding 研究中的人機分工與領域專業](/blog/26-anthropic-agentic-coding-expertise/)值得搭配閱讀：AI 承接執行後，人仍要決定問題、檢查結果並對成果負責。

本文不把 Anthropic 當成一般公司的縮影。它是 AI 產品開發者，也是把 Claude 深度整合進內部流程的公司；其規模、資料可見度、工具成熟度與商業成長都不尋常。這份第一手資料讓工作重組變得可觀察，卻仍需其他企業、職類與時間跨度的研究，才能回答這些變化是否會擴散、如何影響薪資與就業，以及誰能分享生產力收益。
