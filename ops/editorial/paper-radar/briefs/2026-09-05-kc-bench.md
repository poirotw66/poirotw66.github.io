# KC-Bench: A Dynamic Interactive Benchmark for Evaluating Knowledge Conflicts in LLM Agents

## Identity

- Stable ID: `arxiv:2609.03588`.
- Canonical URL: https://arxiv.org/abs/2609.03588
- Authors: Yaxing Lyu, Shengjie Zhou, Binbin Toh, Pengyu Zhu, and Lijun Li.
- Venue or review status: arXiv v1 submitted 2026-09-03; no separate venue record located.
- DOI / OpenReview / arXiv aliases: `10.48550/arXiv.2609.03588`; no separate identifier located.
- Code / model / data: https://github.com/ASTAR123/KC-Bench.

## Editorial fit

- Reader question: Can an agent reconcile user instructions, its prior knowledge, and changing tool evidence before it exposes data or acts?
- Why this belongs in the selected track: It fills `agent-systems` / `agent-evaluation` with an interactive conflict-handling benchmark tied to downstream tool consequences.
- Gap it fills: Existing benchmarks often test factuality or tool-call correctness separately; KC-Bench tests world-knowledge, identity, and temporal multi-source conflicts in one controlled harness.
- Why now: The benchmark reports persistent, domain-dependent weaknesses across nine models and shows how missed conflicts can propagate into synthetic protected-data flows.

## Claim map

- Problem: Agents must detect and resolve conflicts across user messages, parametric knowledge, databases, tool outputs, and time before taking action.
- Main claim: No evaluated model reliably handles factual correction, identity consistency, and temporal conflict resolution across all settings.
- Method: Build 238 manually screened multi-turn tasks from more than 1,000 candidates, with a user simulator, stateful typed tools, deterministic assertions, an open-source evaluator, and human trajectory verification.
- What is genuinely new: The benchmark defines three operational conflict types and makes safe clarification/verification behavior observable at the action boundary.

## Evidence audit

- Datasets and tasks: 238 tasks across Region, Retail, and Personal Assistant domains; task generation and quality-control rules are described and manually screened.
- Metrics: Automatic and human trajectory scores, conflict detection, clarification, tool behavior, and domain-level variation.
- Baselines: Nine models including GPT-5.1, Gemini-3-flash-preview, Claude-haiku-4-5, GLM-4.5-Air, DeepSeek-V4-Flash, GLM-5.2, and MiniMax-M3.
- Statistical uncertainty: Human verification and deterministic assertions strengthen the evidence, but benchmark scale and domain construction remain bounded.
- Threats to validity: The harness standardizes planning, memory, routing, recovery, and authorization; it evaluates model-level behavior rather than complete agent products and uses synthetic protected-data flows.

## Reproducibility

- Available artifacts and licenses: Public GitHub code is linked from the paper; the arXiv record does not establish artifact version or license in the scanned material.
- Environment or compute requirements: A task harness, simulated databases/tools, model access, and evaluator/human verification are needed.
- Smallest useful reproduction: Re-run one conflict type with deterministic tool assertions and compare detection, clarification, and unsafe action rates across two models.
- Blocking unknowns: Repository completeness, dataset release format, exact evaluator prompts, inference cost, and transfer to real customer data or production authorization layers.

## Critical reading

- Strongest result: Cross-domain variation is large enough that a single aggregate task-success score would conceal important failure modes.
- Weakest assumption: Standardizing the harness isolates model behavior without removing the very planning, memory, recovery, and authorization interactions that shape production outcomes.
- Stated limitations: The paper explicitly places framework comparison outside scope and avoids causal claims about training mechanisms such as RLHF.
- Claims not supported by the evidence: The results do not rank agent frameworks, prove real-data leakage, or establish a universal conflict-resolution strategy.
