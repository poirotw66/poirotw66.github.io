# Bloss0m UI Guideline

本文件是 Bloss0m 網站的 UI／UX 實作規範，對應 `AGENTS.md` 的 PRD-003。新增或修改頁面時，應優先沿用既有設計 token、共用元件與頁面類型樣式，並以行動版長文閱讀體驗、無障礙及效能預算作為驗收條件。

## 1. 設計目標

1. **內容優先**：視覺層級服務於閱讀、掃描與導覽，不讓裝飾壓過文章和專案內容。
2. **溫暖而理性**：預設暖色主題使用奶油底與銅色重點；深色主題使用海軍藍底與藍色重點。
3. **輕量深度**：使用表面色差、1px 邊框與有限陰影表現層次，避免厚重玻璃效果或大面積高對比陰影。
4. **雙語一致**：繁中與英文頁面應共享相同資訊架構、元件與互動；翻譯長度差異不得造成溢位。
5. **行動版優先**：先確保 390px 寬度下的導覽、長文、卡片與表單可用，再擴展桌面版。

## 2. 設計 token

Token 的唯一實作來源是 `public/css/base.css`。元件不得自行複製主題色；若需要新語意色，應先新增語意 token，再於兩個主題中定義。

### 2.1 色彩

| 用途 | 暖色主題 | 深色主題 | 使用方式 |
| :--- | :--- | :--- | :--- |
| 頁面背景 | `#f5f4ed` | `#0f1219` | `var(--bg)` |
| 一般表面 | `#f0eee6` | `#171c26` | `var(--surface)` |
| 卡片表面 | `#faf9f5` | `#1c222e` | `var(--surface-card)` |
| 主要文字 | `#141413` | `#e8ecf4` | `var(--text)` |
| 次要文字 | `#5e5d59` | `#95a0b5` | `var(--text-muted)` |
| 邊框 | `#e8e6dc` | `#2a3344` | `var(--border)` |
| 主要重點 | `#7a4423` | `#6b90ff` | `var(--accent)` |
| 次要金色 | `#9a7340` | `#c4a05a` | `var(--gold)` |

規則：

- 正文、標題與互動文字必須符合 WCAG AA 對比度；一般文字至少 4.5:1，大字至少 3:1。
- 不以顏色作為唯一的狀態提示；選取、錯誤與成功狀態需搭配文字、圖示或結構提示。
- 主題混色優先使用 `color-mix()` 搭配既有 token，不新增無語意的十六進位顏色。
- 暖色是預設主題；所有新元件必須同時檢查暖色與深色主題。

### 2.2 字體與文字

| 角色 | 字體 |
| :--- | :--- |
| 標題 | Archivo、Noto Sans TC fallback |
| 正文與介面 | Space Grotesk、Noto Sans TC fallback |
| 程式碼、kicker、技術標記 | JetBrains Mono、Fira Code fallback |

- 行動版正文不得小於 `16px`，長文建議使用現有 `--type-body: 1.0625rem`。
- 長文行高至少 `1.7`；介面文字可依密度使用 `1.4–1.6`。
- 長文行寬應沿用 `--prose-max`，不可讓段落在寬螢幕無限制延伸。
- 標題需有清楚層級；每頁只有一個 `h1`，不可只用字級模擬標題。
- 英文標題允許自然換行，不使用固定高度容器裁切文字。

### 2.3 間距、圓角與陰影

- 頁面水平留白使用 `--page-gutter`，內容外框使用 `--layout-max` 或 `--shell-max`。
- 基準間距為 `--space: 1.5rem`；局部間距採 0.25rem 倍數，避免任意像素值。
- 一般元件使用 `--radius`，大型面板使用 `--radius-lg`。
- 靜止卡片以表面色與 1px 邊框建立層次；hover 陰影使用 `--shadow-card-hover`。
- 同一畫面避免超過三種圓角尺度或多組不同陰影語言。

## 3. 響應式版面

### 3.1 基本原則

- CSS 採內容驅動的響應式設計；目前主要切換點為 `900px` 與 `640px`。
- 所有 grid／flex 子項應允許收縮（例如 `min-width: 0`），不得產生水平頁面捲動。
- 觸控目標建議至少 `44 × 44px`；相鄰操作需保留足夠間距。
- 主要內容在 390px、768px、1280px 三種寬度都應可閱讀與操作。

### 3.2 導覽

- 桌面導覽最多顯示五個主要項目：專案、部落格、論文精讀、搜尋、聯絡。
- `<= 900px` 使用選單按鈕；`<= 640px` 維持單列導覽，選單以浮動面板展開，不推動頁面內容。
- 行動版只顯示可切換到的另一語言，避免重複標示目前語言。
- 選單按鈕必須同步 `aria-expanded`，支援 Escape 關閉，並保有可見焦點。
- 導覽不得遮住錨點標題；文章錨點偏移使用 `--article-anchor-offset`。

### 3.3 頁面類型

- **首頁**：建立品牌與內容入口；每個區塊只保留一個主要行動。
- **Hub／列表頁**：優先支援快速掃描。行動版使用縮圖＋內容的緊湊排列，摘要最多顯示三行。
- **文章／專案詳細頁**：優先支援長文閱讀；正文、目錄、程式碼、表格及嵌入媒體不得超出容器。
- **搜尋／篩選頁**：標籤永遠與控制項可見關聯；空結果需說明原因並提供清除篩選的下一步。
- **聯絡與錯誤頁**：主行動必須在首屏可辨識，避免只有裝飾而沒有出口。

## 4. 元件規範

### 4.1 卡片與列表

- 整張卡片可點擊時，內部不得再放置造成重疊互動的連結。
- 裝飾性圖片連結應設 `aria-hidden="true"` 與 `tabindex="-1"`；標題連結提供可理解的名稱。
- 圖片必須提供正確的 `width`、`height` 或 `aspect-ratio`，避免 CLS。
- 封面優先使用 WebP；重要圖片提供有意義的替代文字，純裝飾圖片使用空 `alt`。
- hover 可使用輕微位移、邊框或陰影，但內容與按鈕不可因 hover 重新排版。

### 4.2 按鈕與連結

- 主要行動使用 `.btn-primary`，同一區塊通常只有一個主要按鈕。
- 次要行動使用 `.btn-secondary` 或文字連結；不使用外觀相同但語意不同的 `<div>`。
- 所有互動元素都必須有 `:focus-visible` 樣式，不能只提供 hover 狀態。
- 連結文字應描述目的；避免單獨使用「點這裡」或無名稱圖示。
- 外部連結若開新分頁，需讓使用者可預期其行為。

### 4.3 表單與篩選

- 每個輸入元件都要有可見 `<label>` 或等效的無障礙名稱。
- 錯誤訊息應靠近欄位並說明修正方式；不可只改變邊框顏色。
- 搜尋與篩選需保留無 JavaScript 的基本內容可讀性。
- 清除篩選與載入更多等狀態變化應維持鍵盤焦點合理位置。

### 4.4 長文內容

- 正文段落行高至少 1.7，避免過密的段落間距。
- 表格與程式碼在窄螢幕允許容器內水平捲動，不得讓整頁橫向捲動。
- 引言、提示、程式碼與一般段落需有明確但克制的視覺差異。
- YouTube、PDF 與 Mermaid 等嵌入需保留標題或替代說明，並檢查行動版高度與載入行為。

## 5. 動效與互動回饋

- 一般轉場沿用 `--transition: 220ms ease`。
- 動效只用於說明狀態、回饋操作或輔助層級，不加入持續循環的裝飾動畫。
- 必須尊重 `prefers-reduced-motion: reduce`；必要功能不可依賴動畫完成。
- 避免會改變版面幾何的 hover 效果；優先使用 `transform`、顏色、邊框與陰影。

## 6. 無障礙基線

所有新頁面與元件至少符合下列要求：

1. 頁面具備唯一且描述性的 `<title>`、一個 `<main>` 與一個 `<h1>`。
2. HTML `lang`、導覽名稱、表單標籤及語言切換名稱正確。
3. 可以只用鍵盤完成導覽、開關選單、操作篩選與啟動主要功能。
4. 焦點順序與視覺順序一致，焦點指示清楚可見。
5. 裝飾內容不進入 Tab 順序；有意義圖片具備適當替代文字。
6. 文字與互動元件符合 WCAG AA 對比度。
7. 不以 placeholder 取代 label，不以顏色或動畫作為唯一訊息來源。

Lighthouse Accessibility 應維持 `1.00`；但 Lighthouse 不能取代鍵盤、螢幕閱讀器語意與實際內容檢查。

## 7. 效能與穩定性

UI 調整不得突破 `docs/current-state.md` 與建置腳本定義的預算。當文件數字與腳本不同時，以 `scripts/check-performance-assets.mjs` 及 Lighthouse 設定為準，並同步更新文件。

- 圖片需設定尺寸並使用適當解析度，首屏以外內容採延遲載入。
- 避免為單一元件引入新的全站套件或字型。
- 新 CSS 放置原則：token／reset 放 `base.css`，共用殼層放 `layout.css`，頁面類型分別放 `home.css`、`hub.css`、`article.css`。
- Astro scoped styles 僅用於小型且真正隔離的元件。
- Blog index 首屏 HTML 維持有限文章量，完整資料由靜態 JSON 漸進增強載入。
- Core Web Vitals 目標：LCP `<= 2.5s`、CLS `<= 0.10`、正式環境 INP p75 `<= 200ms`。

## 8. 新頁面與 PR 驗收清單

### 設計與內容

- [ ] 暖色與深色主題均正常，未直接複製主題色。
- [ ] 資訊層級清楚，每區只有一個主要行動。
- [ ] 繁中與英文內容都不溢位、不被固定高度裁切。
- [ ] 圖片比例、替代文字與載入策略正確。

### 響應式與互動

- [ ] 已檢查 390px、768px、1280px 寬度。
- [ ] 無整頁水平捲動，導覽與浮動元件不遮擋內容。
- [ ] 鍵盤可完成所有操作，Escape、焦點與狀態回饋合理。
- [ ] `prefers-reduced-motion` 下仍可完整使用。

### 自動驗證

- [ ] `npm run build`
- [ ] `npm run test:tags`
- [ ] `npm run test:reading-quality`
- [ ] `npm run test:i18n`
- [ ] 建置後執行 `npm run test:performance`
- [ ] 代表頁面的 Lighthouse Accessibility 為 `1.00`

## 9. 維護原則

- 規範描述「應維持的產品行為」，CSS 描述「目前的實作」。兩者有落差時，需在同一個變更中決定修正實作或更新規範。
- 新增全站模式前先確認能否擴充既有元件，避免同功能出現多套卡片、按鈕或頁首。
- 每次大幅 UI 改版都應更新本文件、`docs/current-state.md` 的實測數字，以及必要的 Lighthouse／資產預算。
