## 1. 目的與設計決策

讓首次造訪者在首屏辨認「Justin／Bloss0m、AI 工程專業、代表案例入口」，並透過可查驗的作品圖像形成品牌記憶。長文頁延續舒適閱讀，首頁與列表增加展示力。

採用「有溫度的 AI 工程誌＋作品展廳」方向：奶油白與銅色、開放式排版、明確的大小對比、真實工程圖像，以及節制的花花註記。

本文件交付的是實作規格，不代表已有視覺稿、效能實測或部署結果。後續先製作代表畫面再實作，視覺稿確認是設計里程碑，不代表發佈授權。

### 1.1 範圍

- 全站導覽、色彩使用、字體層級、按鈕、圖片展示與頁尾。
- 首頁完整構圖；部落格、論文與專案列表。
- 長文與專案詳情頁；關於與聯絡頁。
- 繁中／英文、暖色／深色與桌面／平板／手機。
- 素材清單、元件責任、分批實作及驗收。

### 1.2 非目標

- 不遷移 Astro、不導入 CMS、會員、付費功能或新分析服務。
- 不變更文章事實、發表日期、成果數字、canonical、slug 或分類策略。
- 不因改版刪除搜尋、篩選、RSS、PDF、數學、程式碼、目錄或既有閱讀路徑。
- 不製作假的產品畫面、客戶標誌、評測數據或演講照片。
- 不以新增動效套件或全站字型作為美感提升的前提。

## 3. 設計系統

### 3.1 色彩與表面

沿用 `public/css/base.css` 的語意 token；本表是指定使用方式，不建立另一份執行時色彩來源。

| 角色 | 暖色 | 深色 | 使用規則 |
| --- | --- | --- | --- |
| 背景 | `#f5f4ed` | `#0f1219` | 頁面大面積底色 |
| 次層表面 | `#f0eee6` | `#171c26` | 篩選、摘要、局部展示底 |
| 圖版表面 | `#faf9f5` | `#1c222e` | 圖像襯底與必要面板 |
| 主文字 | `#141413` | `#e8ecf4` | 標題與正文 |
| 次文字 | `#5e5d59` | `#95a0b5` | 圖說、日期與補充說明 |
| 強調色 | `#7a4423` | `#6b90ff` | 主行動、選取狀態、少量工程圖重點 |
| 分隔線 | `#e8e6dc` | `#2a3344` | 裝飾分隔；不能單獨承擔控制項識別 |

- 首頁及列表移除大面積裝飾光暈；長文正文底不顯示格線或材質。
- 工程圖版可使用低對比細格線，限定在圖版範圍內。
- 暖色版不插入突然變黑的整段區塊；深色版需單獨校準圖片襯底與文字對比。
- 靜止元件不使用浮起的大陰影；hover 限輕微陰影或線色變化。
- 圓角只保留三個尺度：控制項 8px、圖像 12px、大型圖版 16px。主要頁面區塊不包圓角外框。
- 主按鈕改為實色，文字對比須實測；深色版藍底不可直接假設白字合格。

### 3.2 字體與字級

Archivo 用於拉丁標題、Space Grotesk 用於拉丁內文、JetBrains Mono 用於程式碼與少量編號。繁中沿用既有 fallback，須在實際環境檢查字面、標點與字重；目前自架字型檔只涵蓋 Latin，不假設 Noto Sans TC 已載入。

下列數值為 CSS px／倍率；實作使用 rem 與流動字級，不固定文字容器高度。

| 角色 | >900px | 641–900px | ≤640px | 字重／行高 |
| --- | --- | --- | --- | --- |
| 首頁主標 | 56–68 | 44–52 | 34–40 | 600–700；繁中 1.18、英文 1.08–1.15 |
| 內頁主標 | 40–48 | 36–42 | 28–34 | 600–700；1.2–1.3 |
| 區塊標題 | 32–40 | 28–32 | 24–28 | 600；1.25–1.35 |
| 項目標題 | 22–28 | 22–26 | 20–24 | 600；1.35 |
| 長文正文 | 18 | 17–18 | 17 | 400；1.8 |
| 介面文字 | 16 | 16 | 16 | 400–500；1.5 |
| 圖說／日期 | 14 | 14 | 14 | 400–500；1.5 |
| 短編號／kicker | 12–13 | 12–13 | 12–13 | 500；1.4 |

- 中文標題 letter-spacing 介於 -0.02em 至 0；英文大標可到 -0.035em。
- 只對短英文標記使用全大寫與正字距，不把整段中英副標轉大寫。
- 中文段落目標每行約 32–40 個全形字；英文約 60–75 字元，透過語言別行寬限制達成。寬圖、程式碼與表格可突破正文欄，不擴張段落行寬。
- 標題自然換行，不使用 nowrap 強壓，也不以縮到正文大小解決英文溢位。
- 數字使用等寬數字特性；成果數字必須與口徑說明一起出現。

| 項目 | 桌面 | 平板 | 手機 |

## 4. 全站殼層

### 4.1 導覽

- 桌面高度目標 72px、手機 60px；字樣與品牌圖左對齊，導覽居中，工具靠右。
- 主要入口：專案、部落格、論文精讀、關於與聯絡；搜尋以具名稱的獨立工具提供。Now 保留頁尾與內容入口。
- 導覽群組移除大型膠囊背景；目前頁面用底線或底色加字重表示。
- 語言與主題控制保留現有行為，視覺權重低於主要導覽。
- ≤900px 使用既有選單模式；手機維持單列，觸控範圍至少 44×44px。
- 選單保留 Escape、aria-expanded、可見焦點與合理焦點回復。

### 4.2 連結、卡片與狀態

- 一區一個主要 CTA，其餘採文字連結；不在每個文章項目重複放大型按鈕。
- hover 180–220ms；圖片最多放大至 1.02，容器不改變尺寸。鍵盤 focus 提供同等資訊。
- 所有內容預設可見；JS 未載入或減少動態時不得留下透明區塊。
- 搜尋保留查無結果、清除、載入、載入失敗重試與載入完成狀態；載入更多後焦點不得跳回頁首。
- 單張卡片不巢狀互動；有多個標籤連結時只讓標題／圖片成為主要入口。

## 5. 首頁規格

### 5.1 頁面順序與錨點

| 順序 | 區塊 | 目標 |
| --- | --- | --- |
| H01 | Hero | 品牌、主張與代表案例入口 |
| H02 | 證據列 | 三項成果與查驗入口 |
| H03 | 旗艦作品＋其他案例 | 用圖像呈現可運行系統 |
| H04 | 精選文章 | 讓讀者進入代表性工程內容 |
| H05 | 主題探索 | 依 Agent／RAG／Platform 問題導讀 |
| H06 | 作者與合作 | 建立真人連結並提供邀請入口 |
| H07 | Footer | 精簡探索與品牌收尾 |

保留 `#hero`、`#trust`、`#showcase`、`#updates`、`#focus`、`#other-cases`、`#cta` 可解析。H04 可沿用 `#updates` 作為相容 ID，但可見名稱改為「精選工程文章」。實作前盤點既有 hash 處理器；仍被使用的舊錨點須映射至合理目的地，不能直接移除。

### 5.2 H01：品牌首屏

- 桌面左 7 欄文字、右 5 欄工程主視覺，垂直光學置中，不包大型文字卡片。
- 中文主標沿用「把前沿 AI，做成真正能運行的系統。」；英文沿用「Turn frontier AI into systems that actually run.」。可依語言安排換行，不逐字套用相同斷行。
- 副標最多約三行；主 CTA「查看代表案例」指向 `#showcase`，次入口「瀏覽全部專案」指向語言對應專案列表。
- 主視覺是可讀的四段工程示意：文件、檢索、Agent、評測；使用真實架構的簡化表示，圖說標示「工程流程示意」。
- 桌面圖版約 480–540px 寬，4:3；不將密集架構總圖縮成不可讀的小圖。
- 花花為圖版旁註或邊角標記，尺寸 48–64px；不再佔用獨立高卡片。
- ≤900px 改單欄：文字 → CTA → 圖版。≤640px 圖版採簡化橫式 8:5，保留主要流程文字。
- 1280×800、390×844 下，主標、完整副標與主 CTA 必須在首屏可見。手機圖版可落在下一屏，不為塞入首屏縮小文字。

### 5.3 H02：證據列

- 桌面三欄細線分隔；手機三行，數字靠左、口徑與連結靠右。
- 沿用目前有資料依據的 98.0%、19、5+，實作時回查來源，不能因視覺需求改數字。
- 「固定 100 題 benchmark」等限定說明不可在手機隱藏。
- 本區與旗艦案例共用資料；避免複製成果字串成為第二個事實來源。

### 5.4 H03：作品展示

- Agentic RAG 為主要展示：桌面 7 欄圖像、5 欄內容；手機先標題與一句成果，再圖像、說明與連結。
- 使用完整可讀的架構圖／真實輸出；含文字圖版採 contain、配主題襯底。
- 摘要僅呈現「問題、關鍵決策、結果」，各一個短段落；細節保留在案例頁。
- OCR、LINE 工作流接在下方，桌面兩個較小作品、手機單欄；各有圖像、名稱、一句成果。
- 首頁數據保留 benchmark／實作範圍，不將內部測試成果概括成所有正式環境表現。

### 5.5 H04：精選文章

- 沿用既有三篇精選資料，第一篇佔 7 欄大圖，另外兩篇佔 5 欄上下排列；手機依序單欄。
- 只顯示封面、分類、標題、日期與一句摘要。標題不截斷；摘要最多三行。
- 區塊名稱「精選工程文章」／「Selected engineering writing」。
- 若呈現近期更新，另設精簡文字列，排序與日期來自實際內容資料；不將人工精選冒充最新。

### 5.6 H05–H07：探索、作者與收尾

- 主題探索使用三列編號、主題名稱、一句問題與箭頭，不再複製三個完整卡片框。
- 每列連到既有指南／主題入口；先驗證中英路由存在，再定案文案。
- 合作區桌面照片 5 欄、文字 7 欄；手機照片縮為輔助比例，邀請入口優先。
- 有公開且獲准使用的真實演講照片才使用；缺素材時採作者文字簡介與現有演講紀錄，版面不得保留空框。
- 頁尾保留探索、Now、花花實驗室及現有必要聲明；品牌字樣與小型花花只出現一次。

## 7. 素材與圖片交付

| Asset ID | 交付 | 來源與處理 | 備援 |
| --- | --- | --- | --- |
| A01 | Hero 工程示意，桌面4:3／手機8:5 | 依實際架構重繪 SVG 或 HTML；文字可讀、有文字等價內容 | 四段靜態流程，不依賴動畫 |
| A02 | RAG 旗艦圖版，8:5 | 優先現有真實架構圖；完整展示、附圖說 | 使用現有封面 contain，不裁文字 |
| A03 | OCR／LINE 作品圖，各8:5 | 經去識別處理且可公開的輸出或流程圖 | 以有依據的架構示意替代，標明示意 |
| A04 | 三篇精選封面，各8:5 | 先審查現有封面；只重製不適用者 | 統一襯底、完整展示 |
| A05 | 作者／演講照片，建議4:5 | 使用本人提供或已獲准的真實素材；記錄來源 | 文字作者區＋公開演講紀錄 |
| A06 | 花花小型導覽圖 | 沿用現有角色素材；48／64px 顯示仍可辨認 | 品牌既有縮圖 |

- 含字圖片與完整流程圖預設 contain；只有不含關鍵邊緣資訊的照片／插畫可以 cover。
- cover 素材四邊各保留約 10% 安全區，並以實際縮圖檢查；無法保留關鍵資訊時改 contain。
- 標題、日期與數字由 HTML 呈現；不把主要網頁文字烘焙進圖片。
- 保留現有 200×125、480×300、1200×750 衍生流程；不同 Hero 比例使用獨立素材，不扭曲原圖。
- 所有圖片設定尺寸／比例；僅實際 LCP 候選採 eager，其餘依位置 lazy。SVG 不內嵌大型 bitmap。
- 新 raster 圖目標：手機使用版本≤100KB、桌面主圖≤180KB；屬新增素材目標，尚非現有 CI 門檻，需在交付表逐張記錄。
- 每項交付記錄來源、用途、尺寸、檔案大小、替代文字、裁切方式及雙主題呈現。

## 10. 驗收規格

### 10.1 畫面矩陣

- 首頁、部落格列表、論文列表、專案列表、代表長文、RAG 案例、聯絡頁：各檢查 390×844、768×1024、1280×800，涵蓋 zh／en × warm／dark。
- 額外檢查 320px 窄螢幕與 200% 縮放；不得整頁水平捲動或遮住主要操作。
- 搜尋、404、Now、Lab 抽查390px與1280px，兩主題各至少一組。
- P0 保存同 viewport 基準，P4 用相同內容與尺寸比較。未取得的基準標示缺漏，不能用推測結果替代。

### 10.2 必須通過的視覺與互動條件

- [ ] 首頁第一屏完整顯示品牌主張、副標與案例 CTA。
- [ ] Hero 圖像、旗艦圖像與精選封面建立三個明確視覺重點。
- [ ] 部落格桌面首屏可見精選文章，而非只有篩選表單。
- [ ] 主要區塊不再由相同大型圓角框逐段包住；沒有三層框中框。
- [ ] 代表圖版關鍵字與節點完整；手機仍可讀，必要時提供原圖連結。
- [ ] 圖像、版面順序與 metadata 在兩語言一致；標題不被固定高度裁切。
- [ ] 成果口徑、日期、來源與合作入口未因精簡視覺而失真。
- [ ] 普通文字對比≥4.5:1，大字≥3:1；必要控制項邊界與焦點對比≥3:1。
- [ ] 手機長文≥16px、行高≥1.7；本次設計目標為17px／1.8。
- [ ] 鍵盤可完成導覽、選單、篩選與載入更多；焦點可見且順序合理。
- [ ] 減少動態與 JS 不可用時，文章、主連結與圖片仍可見。
- [ ] 主題、語言、RSS、搜尋、閱讀路徑、舊錨點與嵌入功能回歸正常。

### 10.3 效能與測試

目前已確認的硬門檻包括首頁 CSS 86KiB、Hub CSS 54KiB、Preview Hub CSS 57KiB、Blog Hub CSS 60KiB、Article CSS 55KiB、首頁 HTML 每語言48KiB、Blog index HTML 每語言70KiB。完整範圍與其他條件以腳本為準，不為本次設計默默提高預算。

- 設計體驗目標 LCP≤2.5s、CLS≤0.10；Lighthouse hard gate 以現有設定執行並記錄實測值。
- 正式環境 INP p75≤200ms 為上線後觀測目標；本地 Lighthouse／TBT 不能宣稱已驗證正式環境 INP。
- `npm run build`、`npm run test:performance` 必須通過；Accessibility 目標1.00，另做手動鍵盤檢查。
- 執行現有 `test:home-brand`、`test:home-roadmap`、`test:home-roadmap:render`、`test:blog-index`、`test:covers`、`test:toc`、`test:i18n` 等與實際變更相關測試；舊測試若綁定已改版行為，依本規格調整斷言，保留有效相容性檢查。
- 不為純色彩或間距增加鏡像單元測試；新增行為與回歸風險才補測試。
- 最終 review 檢查 diff、死碼、重複 CSS 覆寫、未使用 import、圖檔大小與非本次修改。

## 11. 尚待實作前確認的素材與風險

| 項目 | 決策／處理 |
| --- | --- |
| 作者照片來源尚未盤點 | 不阻塞首頁其他區塊；無可用素材採文字版本 |
| 圖版重製可能擴大工作量 | 優先 A01、A02；其餘先校正現有展示比例 |
| 中文 fallback 跨平台差異 | 實機檢查 macOS／Windows 可用環境；未測環境列為限制；新增 CJK 字型需另評估載入成本 |
| 全站 token 影響其他頁 | P1 同時做搜尋、404、Lab、Now 回歸，不等全站完成才檢查 |
| 增加圖片影響 LCP | 響應式尺寸、明確寬高、控制 eager 圖數；優先簡化素材後再考慮其他優化 |
| 新構圖改變閱讀順序 | DOM 順序以手機閱讀順序為基礎，CSS 不製造視覺與鍵盤順序分離 |
| 既有編輯工作進行中 | 保留所有非本次變更，不回復或混入 Radar／內容修改 |

## 12. 完成定義

改版完成須同時具備：代表畫面與全站設計一致、真實素材來源可追溯、雙語雙主題主要頁通過矩陣、原功能保持可用、build 與效能 gate 通過，以及可 review 的變更與驗收紀錄。只改色票、只交首頁截圖或只通過 build，均不算完成本規格。
